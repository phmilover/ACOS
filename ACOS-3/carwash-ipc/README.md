# Автомойка IPC (вариант 43)

Имитация автоматической автомойки на взаимодействующих процессах, C17: libc и системные вызовы.
Процесс на каждую машину, каждый пост и координатора. Четыре программы на одной модели:

| Программа | Процессы | Синхронизация | Обмен данными |
|---|---|---|---|
| `cw1` (4-5 баллов) | родитель порождает детей (`fork`) | именованные семафоры POSIX | разделяемая память POSIX |
| `cw2` (6 баллов) | родитель порождает детей (`fork`) | неименованные семафоры в разделяемой памяти | разделяемая память POSIX |
| `cw3-*` (7-8 баллов) | независимые программы | именованные семафоры POSIX | разделяемая память POSIX |
| `cw4-*` (9-10 баллов) | независимые программы | именованные семафоры POSIX | именованные каналы (FIFO) |

Многопоточные версии - `ACOS-2/carwash-mt` и `ACOS-2/carwash-mon`, последовательная -
`ACOS-1/carwash`.

Проверено на Linux (Ubuntu, ядро 7.0, aarch64, gcc 15 и clang 21) и на macOS (Apple clang 21).
На macOS нет `sem_init` для семафоров между процессами (возвращает `ENOSYS`), поэтому `cw2`
там сообщает об этом и выходит с кодом 5; остальные программы работают на обеих
системах.

## Сборка и запуск

Все команды - из папки `carwash-ipc`.

```bash
make                                   # всё в bin/
./bin/cw1                              # обычный день: родитель и дочерние процессы
./bin/cw2 -c data/rush-hour.cfg        # то же на неименованных семафорах (Linux)
scripts/run3.sh                        # программа 3: все участники одной командой
scripts/run4.sh -c data/breakdowns.cfg # программа 4
./bin/cw1 -u                           # без конца дня, остановка по Ctrl+C
./bin/cw1 -h                           # все ключи
make test                              # сценарные тесты всех программ
make asan && tests/run_tests.sh bin-asan   # те же тесты под ASan и UBSan
```

Программы 3 и 4 можно запускать и по частям, в любом порядке, из разных терминалов:

```bash
./bin/cw3-coord -k demo                # создаёт объекты IPC и ждёт участников
./bin/cw3-post -k demo prewash 1       # по процессу на пост: стадия и номер поста
./bin/cw3-post -k demo tunnel 1
./bin/cw3-post -k demo tunnel 2        # ... и так для всех постов конфигурации
./bin/cw3-cars -k demo                 # источник машин; въезд открывается, когда все на месте
tail -f carwash.log                    # общая лента всех процессов
```

Ключи координаторов (`cw1`, `cw2`, `cw3-coord`, `cw4-coord`):

| Ключ | Что делает |
|---|---|
| `-c FILE` | файл конфигурации (формат - `data/normal.cfg`) |
| `-s SEED` | seed генератора: каждая машина и каждый пост берут свою последовательность |
| `-d MS` | сколько миллисекунд длится минута модели (по умолчанию 100) |
| `-l FILE` | журнал, по умолчанию `carwash.log` |
| `-u` | без конца дня и без ограничения числа машин |
| `-q` | события только в журнал, на экран - итоги |
| `-k KEY` | (программы 3 и 4) ключ, по которому участники находят друг друга |

Сигналы:

| Сигнал | Кому | Что происходит |
|---|---|---|
| `SIGINT`, `SIGTERM` | любому участнику | остановить всю линию: итоги, журнал, удаление объектов IPC, код 3 |
| `SIGUSR1` | координатору (в программах 1-3 любому) | напечатать состояние очередей и постов |
| `SIGUSR2` | координатору (в программах 1-3 любому) | закрыть въезд досрочно, домыть принятые машины, код 0 |

Коды выхода: `0` - въезд закрыт и все принятые машины вымыты, `1` - плохие параметры,
`2` - ни одну программу обслуживания выполнить нельзя, `3` - прервали сигналом, `4` - нарушен
инвариант, `5` - не удалось создать объекты IPC или процесс, участник пропал.

## Модель

Стадии идут по линии: `prewash`, `tunnel`, `wax`, `dry`. У стадии несколько постов (каждый
моет одну машину) и накопитель ограниченной вместимости перед ней. Машина выбирает программу
по весам и проходит её маршрут по порядку. Закончив операцию, она ждёт места в накопителе
следующей стадии, не уходя с поста, поэтому заполненная стадия останавливает предыдущие.
Если накопителя у следующей стадии нет (`queue = 0`), машина ждёт на посту свободный пост
следующей стадии. Свободный пост берёт машину из накопителя по правилу `fifo`, `program`
(приоритет программы) или `shortest` (меньше всего стадий осталось). После каждой операции пост
может сломаться; сломанный пост не начинает новую операцию, пока его не починят. Машина, чья
первая очередь полна, уезжает; машина, чья программа требует стадию без постов, получает отказ.

Инварианты проверяются при каждом изменении состояния (`src/common/state.c`, функция `StCheck`):
I1 - на посту не больше одной машины, I2 - машина в одном месте (одна очередь или один пост),
I3 - стадии идут в порядке программы, I4 - сломанный пост не начинает операцию, I5 -
накопитель не переполнен. Нарушение печатается в ленту и даёт код выхода 4.

## Как процессы взаимодействуют

**Программы 1-3.** Всё состояние (`State`: машины, посты, накопители, статистика) - в одном
сегменте разделяемой памяти. Семафоры:

| Семафор | Начальное значение | Кто ждёт | Кто поднимает |
|---|---|---|---|
| `SEM_MUTEX` | 1 | все перед изменением состояния и выводом события | тот же процесс |
| `SEM_QUEUE(s)` | вместимость накопителя | машина, прежде чем уйти с поста на стадию `s` | пост, забравший машину из накопителя |
| `SEM_WORK(s)` | 0 | свободный пост стадии `s` | машина, вставшая в ожидание поста |
| `SEM_CAR(c)` | 0 | машина: «заезжай», «операция закончена» | пост |
| `SEM_POST(s,p)` | 0 | пост: машина съехала | машина |
| `SEM_COORD` | 0 | координатор | машина уехала, пост зарегистрировался, сигнал |
| `SEM_OPEN` | 0 | источник машин программы 3 | координатор, когда все посты на месте |

```
машина ─sem_post(WORK s)──► пост стадии s ─StDispatch: машину на пост─► sem_post(CAR c)
   ▲                                │ операция (сон)                          │
   │                                └──────── sem_post(CAR c) ─────────────────┤
   │                                                                          ▼
   │                  машина: sem_wait(QUEUE next) - ждёт места, держа пост
   └──── следующая стадия ◄── sem_post(POST s,p) - пост свободен, может сломаться
```

Остановка: координатор ставит в сегменте флаг `stop` и поднимает все семафоры, на которых
кто-то может ждать; каждый процесс после пробуждения видит флаг и выходит. Сигналы ставят
только флаги (`sig_atomic_t`), обработчики без `SA_RESTART`, поэтому `sem_wait` и `nanosleep`
прерываются с `EINTR` и процесс сразу видит флаг.

**Программа 4.** Разделяемой памяти нет. Координатор - единственный владелец `State`; он
читает сообщения фиксированного размера (меньше `PIPE_BUF`, поэтому запись атомарна) из общего
канала `/tmp/<key>/coord` и отвечает каждому в его канал `/tmp/<key>/p<pid>`. Именованные
семафоры: `/<key>.q<s>` - места в накопителях (машина ждёт на них, держа пост, как в программах
1-3), `/<key>.open` - открытие въезда. Если координатор пропал, участник получает конец файла
в своём канале и выходит.

## Ограничения

- `cw2` работает только на Linux: на macOS неименованные семафоры между процессами не
  поддерживаются.
- Время модели идёт по реальным часам (`-d` мс на минуту), поэтому при одном и том же seed
  выбор программ и длительности совпадают, а порядок событий может немного отличаться.
- Если участника убить `kill -9`, он не успевает сообщить об уходе, и машины, которые его
  ждут, могут встать навсегда. Линию тогда останавливает Ctrl+C (или `SIGTERM`) любому живому
  участнику: координатор ждёт отключения остальных не дольше 5 секунд и удаляет объекты IPC.
  В программах 1 и 2 на Linux дети получают `SIGTERM`, если убит родитель (`PR_SET_PDEATHSIG`).
  Если убит сам координатор, объекты IPC остаются; программы 3 и 4 удаляют их при следующем
  запуске с тем же ключом, а вручную их удаляет `bin/ipc-left -r KEY` (ключ программ 1 и 2 -
  `cw1-<pid>` или `cw2-<pid>`).
