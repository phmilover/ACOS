# Автомойка по сети (вариант 43)

Имитация автоматической автомойки как клиент-серверное приложение на TCP, C17: libc,
системные вызовы и сокеты BSD. Четыре программы:

| Программа | Роль | Сколько запускать | Что видит |
|---|---|---|---|
| `cw-server` | владелец состояния линии: очереди, посты, машины, правила | один | полную ленту событий и итоги |
| `cw-post` | пост мойки: выполняет операции, ломается и чинится | по одному на пост | свои машины и свои поломки |
| `cw-cars` | источник машин: когда приезжает машина и какую программу берёт | один | судьбу своих машин |
| `cw-view` | наблюдатель: панель всей линии в реальном времени | сколько угодно | всё: очереди, посты, клиенты, лента |

Предыдущие версии той же модели: последовательная `ACOS-1/carwash`, многопоточные
`ACOS-2/carwash-mt` и `ACOS-2/carwash-mon`, на процессах `ACOS-3/carwash-ipc`.

Проверено на macOS (Apple clang 21) и Linux (Ubuntu, aarch64, gcc 15), а также в
распределённом режиме: сервер на macOS, посты и наблюдатель - в Linux-машине.

## Сборка и запуск

Все команды - из папки `carwash-net`.

```bash
cmake -S . -B build && cmake --build build   # всё в bin/
scripts/run.sh                             # сервер, все посты и источник машин на этом компьютере
bin/cw-view 127.0.0.1 5050                 # во втором терминале: панель наблюдателя
scripts/run.sh -c data/breakdowns.cfg -d 50   # другой сценарий, 50 мс на минуту модели
```

Каждую программу можно запускать отдельно, в любом порядке, из разных терминалов и с разных
компьютеров. Адрес и порт сервера задаются в командной строке:

```bash
bin/cw-server 0.0.0.0 5050                 # на компьютере A: слушать все интерфейсы
bin/cw-post 192.168.1.10 5050 prewash 1    # на компьютере B: по клиенту на каждый пост
bin/cw-post 192.168.1.10 5050 tunnel 1
bin/cw-post 192.168.1.10 5050 tunnel 2     # ... и так для всех постов конфигурации
bin/cw-cars 192.168.1.10 5050              # источник машин; въезд открывается, когда все на месте
bin/cw-view 192.168.1.10 5050              # на компьютере C: наблюдатель, можно несколько
bin/cw-view -p 192.168.1.10 5050           # наблюдатель в виде ленты строк (для файла или ssh)
```

Ключи сервера (`cw-server [ключи] IP PORT`):

| Ключ | Что делает |
|---|---|
| `-c FILE` | файл конфигурации (формат - `data/normal.cfg`) |
| `-s SEED` | seed генератора: у каждого поста и у источника своя последовательность |
| `-d MS` | сколько миллисекунд длится минута модели (по умолчанию 100) |
| `-l FILE` | журнал, по умолчанию `carwash.log` |
| `-u` | без конца дня и без ограничения числа машин |
| `-q` | события только в журнал, на экран - итоги |

## Тесты, форматирование, clang-tidy, документация

```bash
cmake --build build --target check    # сценарные тесты (tests/run_tests.sh)
cmake --build build --target asan     # те же тесты под ASan и UBSan (сборка в build-asan, bin-asan)
cmake --build build --target format   # clang-format по .clang-format
cmake --build build --target tidy     # clang-tidy по .clang-tidy
cmake --build build --target docs     # Doxygen, открыть build/doxygen/html/index.html
```

Тесты запускают сервер и клиентов на 127.0.0.1 и проверяют коды выхода, журнал и вывод
клиентов; их же запускает `ctest --test-dir build`. Компилятор собирает с
`-Wall -Wextra -Wpedantic -Werror`, clang-tidy проходит без замечаний.

Предусловия функций проверяет `SOFT_ASSERT` (`include/soft_assert.h`): при нарушении он пишет
файл и строку в stderr, а программа продолжает работу, и журнал и итоги не теряются.
Инварианты модели проверяет `StCheck` - это нарушения правил линии, они считаются в итогах.

Для `format` и `tidy` нужны clang-format и clang-tidy: `brew install llvm` (CMake найдёт их в
`/opt/homebrew/opt/llvm/bin`) или `apt install clang-format clang-tidy`. Для `docs` нужен
doxygen. Если чего-то нет, цель напишет, что поставить.

## Подключение, отключение, остановка

- Въезд открывается, когда подключились все посты и источник машин; до этого сервер пишет,
  кого ждёт.
- **Любой клиент можно отключить (Ctrl+C) и запустить снова** - сервер продолжает работу:
  - пост уходит из сети; если он мыл машину, машина остаётся на посту, и когда пост
    вернётся, он выполнит операцию заново; пока поста нет, машины к нему не идут;
  - без источника машин новых прибытий нет, машины на линии домываются; вернувшийся
    источник узнаёт от сервера, сколько машин ещё осталось за день;
  - наблюдатели приходят и уходят как угодно; новый получает конфигурацию, последние события
    и снимок состояния.
- **Остановка сервера останавливает всех клиентов**: сервер рассылает `STOP`, клиенты печатают
  причину и свою статистику и выходят с кодом 0, сервер ждёт их отключения до 3 секунд.
- Если сервер пропал без `STOP` (убит `kill -9`, оборвалась сеть), клиенты видят конец
  соединения и выходят с кодом 5.

Сигналы серверу:

| Сигнал | Что происходит |
|---|---|
| `SIGINT`, `SIGTERM` | остановить линию и всех клиентов: итоги, журнал, код 3 |
| `SIGUSR1` | напечатать состояние очередей, постов и клиентов |
| `SIGUSR2` | закрыть въезд досрочно, домыть принятые машины, код 0 |

Коды выхода сервера: `0` - въезд закрыт и все принятые машины вымыты, `1` - плохие параметры,
`2` - ни одну программу обслуживания выполнить нельзя, `3` - прервали сигналом, `4` - нарушен
инвариант, `5` - не удалось открыть порт. Клиенты: `0` - остановлены сервером или по Ctrl+C,
`1` - плохие параметры или сервер отказал в регистрации, `5` - сервер пропал.

## Модель

Стадии идут по линии: `prewash`, `tunnel`, `wax`, `dry`. У стадии несколько постов (каждый
моет одну машину) и накопитель ограниченной вместимости перед ней. Машина выбирает программу
по весам и проходит её маршрут по порядку. Закончив операцию, она ждёт места в накопителе
следующей стадии, не уходя с поста, поэтому заполненная стадия останавливает предыдущие.
Если накопителя у следующей стадии нет (`queue = 0`), машина ждёт на посту свободный пост
следующей стадии. Свободный пост берёт машину из накопителя по правилу `fifo`, `program`
(приоритет программы) или `shortest` (меньше всего стадий осталось). После каждой операции пост
может сломаться. Машина, чья первая очередь полна, уезжает; машина, чья программа требует
стадию без постов, получает отказ.

Инварианты проверяются при каждом изменении состояния (`src/common/state.c`, `StCheck`):
I1 - на посту не больше одной машины, I2 - машина в одном месте, I3 - стадии идут в порядке
программы, I4 - сломанный пост не начинает операцию, I5 - накопитель не переполнен.
Нарушение печатается в ленту, видно на панели наблюдателя и даёт код выхода 4.

## Что где лежит

```
include/        заголовки; описания структур, полей и функций - в комментариях
src/common/     общее
  config.c        параметры и их разбор         state.c   состояние линии, события, итоги
  util.c          время, сигналы, вывод          rng.c     генератор на сущность
  net.c           TCP: listen, connect, строки   client.c  подключение и часы клиента
src/server.c    сервер: poll по всем соединениям, движение машин, рассылка снимков
src/post.c      клиент-пост
src/cars.c      клиент - источник машин
src/view.c      клиент-наблюдатель: панель и лента
data/           сценарии
tests/          run_tests.sh - сценарные тесты
CMakeLists.txt  сборка и цели check, asan, format, tidy, docs
scripts/        run.sh - запуск сервера и всех клиентов на одном компьютере
```

## Протокол

Текстовый: одно сообщение - одна строка из слов через пробел. Порядок байтов и размеры типов
на разных машинах не важны, а сервер можно проверить руками через `nc 127.0.0.1 5050`.

| Кто → кому | Строка | Смысл |
|---|---|---|
| клиент → сервер | `HELLO post PID STAGE N`, `HELLO cars PID`, `HELLO view PID` | регистрация |
| сервер → клиент | `WELCOME ...` или `REJECT причина` | параметры для этой роли или отказ |
| сервер → все | `OPEN минута`, `STOP код причина` | въезд открыт (и который сейчас час модели); линия остановлена |
| сервер → пост | `SERVE id программа`, `FREE id` | прими машину; машина съехала |
| пост → сервер | `START мин`, `END мин`, `BREAK мин`, `REPAIR`, `IDLE` | ход операции и ремонта |
| источник → сервер | `ARRIVE программа`, `CLOSE n` | машина у въезда; машин больше не будет |
| сервер → источник | `CAR id программа accepted/turned/refused`, `WASHED id программа мин`, `CLOSED` | судьба машин; въезд закрыт |
| сервер → наблюдатель | `STAGE ...`, `PROGRAM ...` | конфигурация линии (при подключении) |
| сервер → наблюдатель | `EV цвет строка` | событие ленты |
| сервер → наблюдатель | `SNAP ...`, `Q ...`, `P ...`, `END` | снимок: счётчики, очереди, посты |
| клиент → сервер | `BYE` | отключаюсь |

## Как устроен сервер

Один поток и один цикл `poll` по слушающему сокету и всем соединениям. TCP - поток байтов,
поэтому у каждого соединения свой буфер, из которого берутся только целые строки (`LineConn`).
Состояние меняется только в этом цикле, последовательно, поэтому блокировки не нужны.
Снимки наблюдателям уходят после изменений, но не чаще 10 раз в секунду, и не реже 2 раз в
секунду, чтобы часы на панели шли.

Время модели идёт по реальным часам (`-d` мс на минуту). Клиенты получают текущую минуту при
регистрации и в `OPEN`, дальше считают её сами, поэтому в их лентах то же время.

## Ограничения

- Время модели идёт по реальным часам, поэтому при одном и том же seed выбор программ и
  длительности совпадают, а порядок событий может немного отличаться.
- Клиент, переставший читать сокет, может задержать сервер не дольше таймаута записи
  (2 секунды), после чего сервер его отключает.
- Только IPv4.
